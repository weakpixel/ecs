# Arity generator (internal/gen → zz_gen_generic-api.go)

Go has no variadic type parameters, so each typed family exists 16 times. `internal/gen` writes these copies.

The spec for the generated API is `doc/api-generic.md`, and the signatures are in `.claude/skills/ecs-core/reference/api.md`.

## Layout

```
generic.go              hand-written: //go:generate go run ./internal/gen
                        + GetComp[T], GetCompOrNil[T], HasComp[T], SetComp[T], RemoveComp[T]
                        + unexported typed helpers the generated code calls
internal/gen/main.go    renders the template for N = 1..16, gofmt (go/format), writes zz_gen_generic-api.go
                        and zz_gen_generic-api_test.go in the module root
internal/gen/templates/*.tpl  text/template, embedded with //go:embed
zz_gen_generic-api.go   output; header "// Code generated by internal/gen; DO NOT EDIT."
```

- `internal/gen` uses the standard library only (`text/template`, `go/format`, `embed`). It doesn't load packages, so it doesn't need `x/tools`.
- Write the output only when it changed (`writeFile` in `main.go`) so `make all` doesn't touch mtimes.
- The output must be deterministic: no maps iterated in the template, no timestamps.

## Keep the generated code thin

Each generated function should be a few lines that call hand-written generic helpers in `generic.go` or other files. That keeps the template small, makes the logic testable once instead of 16 times, and keeps diffs of `zz_gen_generic-api.go` readable. Examples of helpers:

```go
// columnOf returns the typed column for id in a, or nil.
func columnOf[T any](a *archetype, id ComponentID) *typedColumn[T]

// typeIDs resolves component IDs for the type list, panicking on unregistered or duplicate types.
func (w *World) archetypeForIDs(ids []ComponentID) *archetype   // ids from a stack buffer, no alloc
func (w *World) claimEntity(a *archetype) (Entity, int)          // allocates slot, appends entity row, bumps revision
func (w *World) locate(e Entity) (*archetype, int)               // validates (panics if stale), returns archetype+row
```

Then for example `NewEntity3` resolves the 3 IDs into a `[3]ComponentID`, finds the archetype, claims a row and does three typed `append`s, without boxing into `any`.

## Per-family requirements

| Family | Requirement |
| --- | --- |
| `NewEntityN` | 0 allocs/op in steady state. Registers its types on first use (generic API, D3). Duplicate types panic `ecs: duplicate component`. |
| `NewViewN` / `ViewN` | Registers and resolves the IDs in the constructor; panics `ecs: duplicate component` on a repeated type. Holds a pointer to shared state (world, IDs, lazily resolved spawn archetype and typed columns, lazily built query cache). |
| `ViewN.NewEntity` | Claims an entity in the pre-resolved archetype and appends; must be several times faster than `NewEntityN` (the perf guide targets ≈3–4× for N=7). 0 allocs/op. |
| `ViewN.Get` / `Has` | Validate the entity and find its archetype **once** for all N components. `Get` panics `ecs: entity does not have component: <T>` on the first missing one. `View1.Get` returns `*T1`. |
| `ViewN.Set` | Add or replace all N. In place (no revision bump) when the entity has all N; otherwise exactly one move to the union archetype. 0 allocs/op in both cases. |
| `ViewN.Remove` | Removes the components the entity has, in one move; no-op (no revision bump) if it has none. |
| `ViewN.Each` | Wraps the untyped query state (shared archetype cache, revision check) but iterates with typed column slices, not `[]any`. `View1.Each` yields `*T1`, N≥2 yields `ComponentsN` by value. 0 allocs/op per loop. |
| `ComponentsN` | N = 2..16 only. Fields `Comp1..CompN` are pointers in type-parameter order. `Unpack()` returns them as N values. |

The receivers are value receivers on small structs holding a pointer (callers store a `ViewN` by value in their own structs). The zero `ViewN` panics `ecs: not bound to a world`. There is no rebinding method: a view for another world is built with the constructor.

## Avoiding allocations in Each

- `Each()` returns a closure. Keep `Each` small enough to inline so that in `for ... range v.Each()` the closure doesn't escape. Check with `go build -gcflags=-m . 2>&1 | grep -i 'Each'`.
- Inside the closure, hoist the per-archetype typed slices (`c1 := columnOf[T1](a, id1).data`) out of the row loop.
- Don't build a `[]any` or box anything per row.
- Confirm with `testing.AllocsPerRun` tests (see the `ecs-benchmarks` skill), not by eye.

## Testing

- Write tests by hand for N = 1, 2, 3 and 16 of every family (16 catches indexing off-by-ones at the top end). `generic_test.go` holds them.
- `internal/gen` also emits `zz_gen_generic-api_test.go`, a round-trip smoke test for every N, with the same DO-NOT-EDIT header.
- `internal/gen/main_test.go` runs the generator into a temp dir and compares the result with the committed files, so a stale file fails CI.

## Workflow when changing the template

1. Edit `internal/gen/*.tpl` or `main.go`.
2. `go generate ./... && go build ./... && go test ./...`
3. Read the diff of `zz_gen_generic-api.go` for one arity (for example `NewView3`) instead of the whole file.
4. If the change affects the exported API, update `doc/api-generic.md` and `.claude/skills/ecs-core/reference/api.md`.
